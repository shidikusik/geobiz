# Архитектура

Приложение разделено на **платформо-независимое ядро** (чистый C++23, без Qt) и
**Qt-слой** (UI, карты, ввод-вывод). Такое разделение делает бизнес-логику
тестируемой в headless-CI и упрощает перенос между платформами.

```
┌──────────────────────────────────────────────────────────────┐
│                          QML (Material 3)                      │
│   Main · BrowsePanel · DistrictInfoPanel · AiAssistantPanel    │
│   MapView → MapWebDesktop (WebEngine) | MapWebMobile (WebView) │
└───────────────▲───────────────────────────────▲───────────────┘
                │ properties / invokables        │ QWebChannel / injected JS
        ┌───────┴────────┐               ┌───────┴────────┐
        │  ui::AppController │            │  map::MapBridge │
        │  ui::DistrictListModel          └───────▲────────┘
        └───────▲────────┘                        │
                │                                  │  resources/web/map.js
   ┌────────────┴──────────────┐        ┌──────────┴───────────┐
   │      geobiz_core (no Qt)   │        │   Google Maps JS API │
   │  core:: District/Zone/     │        │  Places · Geocoding  │
   │         Metric/Classifier  │        └──────────────────────┘
   │  data:: DistrictRepository │
   │  ai::   QueryEngine        │
   └────────────▲──────────────┘
                │ IDataProvider
   ┌────────────┴──────────────────────────────┐
   │ data::LocalDatasetProvider (Qt JSON) …     │
   │ + будущие провайдеры (Places, госданные)   │
   └────────────────────────────────────────────┘
```

## Слои

### `geobiz_core` — чистый C++23 (библиотека, без Qt)

- **`core`** — доменные типы: `District`, `Indicators`, `Metric` (явное
  отсутствие данных), `Zone`/`ZoneInfo` (таблица цветов), `Classifier`
  (детерминированная классификация с приоритетом рисков), `Geo` (координаты,
  Haversine), `Text` (UTF-8 lower для русского поиска).
- **`data::DistrictRepository`** — агрегирует провайдеров, индексирует по id,
  выполняет классификацию, отдаёт поиск и запросы «дети/родитель».
- **`ai::QueryEngine`** — локальный офлайн-помощник: разбор намерения + гео-скоупа
  из русского текста и ранжирование районов по показателям. Никогда не выдумывает
  ответ: если нужного показателя нет — «Недостаточно данных».

Ядро полностью покрыто тестами (`tests/test_core.cpp`) и собирается пресетом
`core-only` без Qt.

### Qt-слой

- **`app::AppConfig`** — разрешение ключа Google Maps API (env → конфиг-файл) и
  пути к внешнему набору данных.
- **`data::LocalDatasetProvider`** — разбор JSON через `QJsonDocument`.
- **`map::MapBridge`** — единственный контракт между C++ и слоем карты. На десктопе
  публикуется через `QWebChannel`; на мобильных сигналы моста инъектируются в
  страницу через `runJavaScript`, а обратные события приходят навигацией на
  `geobiz://…`.
- **`map::DistrictSerializer`** — компактный JSON (геометрия + цвет зоны + флаг
  «есть данные») для отрисовки на карте.
- **`ui::AppController`** — фасад для QML: асинхронная загрузка (QtConcurrent),
  выбор района, поиск, обращения к ИИ, легенда зон.
- **`ui::DistrictListModel`** — `QAbstractListModel` для списков поиска и ИИ.

## Потоки и производительность

- Загрузка и классификация выполняются в рабочем потоке через
  `QtConcurrent::run`; UI не блокируется. Репозиторий читается только после
  завершения загрузки (`ready == true`).
- Сериализация геометрии происходит в том же рабочем потоке; на главный поток
  передаётся готовая строка полезной нагрузки.
- Отрисовка десятков тысяч объектов делегируется Google Maps (аппаратное
  ускорение) + Qt Quick scene graph; JS-слой отсекает объекты по видимой области.

## Почему разные web-бэкенды

Qt WebEngine (Chromium) доступен только на десктопе. На Android/iOS используется
`QtWebView`, оборачивающий системный web-view. Общими остаются `map.html`,
`map.js` и контракт `MapBridge`; отличается лишь транспорт (QWebChannel против
инъекции JS). Выбор бэкенда — в `qml/components/MapView.qml` по `Qt.platform.os`.
